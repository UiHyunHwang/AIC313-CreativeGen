# Three outward SDXL reveals at 16×16

Spider-Man pulls back into Iron Man, Iron Man into Captain America, and Captain America into the original Spider-Man. Each parent is a separately generated 16×16 field of 1024×1024 SDXL tiles. The native boards measure 16,384 pixels per side. A linked stage occupies one cell in each rendered board. Uncompressed PNG leaves are available under each parent name. The three large JPEGs use high-quality 4:4:4 encoding for viewing. The GIF samples the original in-memory boards.

## Target design and selection

The opening Spider-Man comes from the previous pipeline, generated by SDXL from seed 42. Generate four Iron Man and four Captain America candidates using two text prompts per character, 24 steps, CFG 5 and the seeds recorded in targets/*.json. Based on the eight-candidate contact sheet we shortlisted large helmet portraits (Iron Man indices 0 and 3, Captain America indices 2 and 3). Among the four eligible pairs, targets.py minimizes a score combining the distance to the prior SDXL tile palettes and the best achievable 4×4 color pattern match at each of the three zoom connections. All sixteen pair scores and the explicit composition shortlist are in targets.json. The frozen palette summaries in tile_palettes.json contain only RGB means of previous team-generated SDXL images, plus traceable hashes.

## Tile generation and rendering

Each cell uses the target latent at its own coordinate. During the first five DDIM updates the prompt controls composition with CFG 6.5. During the remaining seven updates CFG is 5. The target's coarse colors guide updates 6 through 10, with a finer latent constraint in bright areas. A deterministic rule reads the target cell's RGB means to describe the local illumination in the text condition. The three pose prompts rotate across the grid. These steps preserve the previous highlight-aware design while adapting to the selected portraits, native 16×16 layout and local color. One final generation per coordinate, with sequential seeds 9130000–9130255, 9131000–9131255 and 9132000–9132255. The render uses all but the one automatically linked position on each board. It does not repaint, recolor or hand-replace individual leaves.

The portal selector compares each potential cell to the complete child mosaic. It scores the lighting and opponent colors on four neighboring borders, the target's 4×4 pattern, the displaced tile and local contrast. Among compatible positions it prefers improvement over the previous border and pattern errors. If none qualifies it minimizes the worst relative difference. Links are solved cyclically until the three previews stop changing. Verification checks the actual child pixels, 5.5-second stops, cumulative durations and decoded first/last frames. The summary measures both the connection error and full-board differences from each version's own target. The common-scale CLIP comparison scores the ordinary leaves at 44 pixels for both grid sizes. It describes recognizability, with different prompts, coordinates and targets between boards.

## Reproduction

From the PhotoQuilt project root, activate the project's creativegen environment and use a local Hugging Face cache with the pinned official SDXL base and CLIP checkpoints.

```bash
export PYTHONPATH=. OMP_NUM_THREADS=2 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1
python outputs/outward_palette16/opening.py
python outputs/outward_palette16/targets.py
python outputs/outward_palette16/generate_boards.py
python outputs/outward_palette16/render16.py
python outputs/outward_palette16/gif_colors.py
python outputs/outward_palette16/quality.py
python outputs/outward_palette16/package_run.py
```

The bundle includes the team's original Spider-Man PNG and latent as a reproducible intermediate, so the opening command is optional. The old overviews used to compare the portal scores come from the previous 8×8 project. The optional CLIP audit can use the original 8×8 PNGs when present. Check render.json, quality.json and generation.json for the run results, measured memory and all native tile hashes. The three full-resolution images and GIF are rebuilt by render16.py. The tile generator can resume by verifying saved PNG hashes against each cell's seed, prompt and parent.
